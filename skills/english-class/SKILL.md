세션 기반으로 동작한다. **시작 → 수업 중 Q&A → 종료(노트 정리)** 세 단계다.

먼저 현재 상태를 확인하고 어느 단계인지 판단한다.

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh status
```

단계 판단 (인자 `$ARGUMENTS` 가 우선):

| 상황 | 단계 |
| --- | --- |
| 인자가 `end` / `끝` / `종료` / `정리` | **C. 종료** |
| 인자가 `start` / `시작`, 또는 인자 없고 진행 중인 세션도 없음 | **A. 시작** |
| 인자 없고 진행 중인 세션이 있음 | **B**로 들어가 대기 (세션 정보를 한 줄 알리고 질문을 받는다) |
| 세션 진행 중에 사용자가 영어 표현을 물음 | **B. 수업 중 Q&A** |
| 세션 진행 중에 "끝", "종료", "정리해줘" | **C. 종료** |

B단계는 스킬을 매번 다시 부르지 않아도 된다. 한 번 시작하면 같은 대화에서 그냥 질문하면 되고, 이 지시가 이미 로드돼 있다. 대화를 새로 시작했더라도 `status` 가 진행 중 세션을 잡아내므로 `/english-class` 한 번이면 이어진다.

## A. 시작

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh start --tutor "이름" --topic "주제"
```

**녹화가 여기서 자동으로 시작된다** (`record.sh start` 를 내부에서 부른다).
`~/Movies/english-class/english-class-<날짜>_<시각>` 프리픽스로 세 파일이 생긴다.

| 파일 | 내용 |
| --- | --- |
| `…-tutor.m4a` | 시스템 오디오 = **강사 목소리**. 헤드셋을 써도 잡힌다 |
| `…-me.m4a` | 마이크 = 내 목소리 |
| `….mov` | 화면 (5fps, 무음. 소리는 위 두 파일에 있다) |

녹음 중에는 **메뉴 막대에 빨간 파형 아이콘**이 뜬다. 아이콘 자체가 입력 레벨에 따라 차오른다.
클릭하면 팝오버가 열려 경과 시간과 **강사 / 나 각각의 음파 파형**을 실시간으로 보여주고,
거기서 바로 "녹음 중지" 를 할 수도 있다.

파형이 말에 맞춰 출렁이면 그 트랙이 살아 있다는 뜻이고, 한쪽이 계속 평평한 기준선이면
그 입력이 안 잡히고 있다는 뜻이다.

- 튜터·주제는 아는 만큼만 넘긴다. 모르면 옵션을 빼고, 굳이 캐묻지 않는다.
- 이미 다른 방법으로 녹화 중이면 `--no-record`, 화면 없이 소리만 남기려면 `--no-video`,
  메뉴 막대가 거슬리면 `--no-menubar`.
- 사용자에게 시작을 알릴 때 **메뉴 막대를 확인하라고 한 줄 덧붙인다.** 수업 초반에 양쪽 막대가
  움직이는지 보면, 50분을 녹음하고 나서야 한쪽이 비었다는 걸 아는 사고를 막을 수 있다.
- 녹화 시작에 실패하면(권한 거부 등) 그 사실을 **반드시 사용자에게 알린다.** 녹화가 없으면
  종료 시 전사할 것도 없다. 조용히 넘어가지 말 것.
- 시작했다고 알리고 — 녹화 중이라는 것과 파일 경로를 포함해서 — 수업 중 궁금한 표현을
  물어보라고 한 줄 안내한 뒤 대기한다. 이후 답변은 짧게 유지한다. 수업 중이라 길게 읽을 시간이 없다.

## B. 수업 중 Q&A

사용자가 표현·문법·단어를 물으면 **간결하게** 답한다.

- 설명 2~3줄 + 예문 2~3개. 예문은 화상 영어 수업/일상 대화 맥락으로.
- 뉘앙스 차이나 더 자연스러운 대안이 있으면 한 줄 덧붙인다.
- 길게 늘어놓지 않는다. 수업 중에 바로 읽고 말해야 한다.

답한 직후 **매번** `~/mylogs/study/.session/qa.md` 에 아래 형식으로 이어 붙인다. 빠뜨리면 종료 시 노트에서 누락된다.

```markdown
## HH:MM Q. (질문)

(설명 한두 줄)

- (예문)
- (예문)
```

## C. 종료

### 1) 녹화 중지 + 재료 모으기

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh end
```

**녹화가 여기서 중지된다.** 세션 메타, 질문 로그(`qa.md`), 녹화 파일 경로와 그 파일을 넘긴
전사 명령이 출력된다. `qa.md` 를 읽는다.

중지는 ffmpeg에 SIGINT를 보내고 최대 30초 기다리는 방식이다. 그 사이에 강제 종료하면 파일이
깨지므로, `end` 가 끝날 때까지 기다린다.

### 2) 녹화 전사

수업 녹화의 **음성**을 전사한다. 화면 캡처가 아니라 오디오가 원본이다.

`end` 가 출력한 전사 명령을 그대로 실행한다.

```bash
~/workspace/stueng/skills/english-class/scripts/transcribe.sh --prefix "<녹화 프리픽스>"
```

- 두 트랙을 각각 mlx-whisper(large-v3-turbo)로 전사한 뒤 시각 순으로 합쳐
  `~/mylogs/study/.session/transcript.md` 를 만든다. 이걸 읽으면 된다.
- **화자는 추정이 아니라 확정이다.** `Tutor` 는 시스템 오디오, `Me` 는 마이크에서 왔다.
- 녹화가 없었으면 `--since <started_at>` 형태가 나온다 — 세션 시작 이후 파일 중 가장 최근 것을
  단일 파일로 전사한다. 이때는 화자 구분이 안 되니, 문맥으로 추정하되 애매하면 `[화자불명]` 으로 둔다.
  파일을 못 찾으면 **멈추고** 녹화본 위치를 물어본다. 아무 파일이나 집지 않는다.
- **오래 걸린다.** 50분 수업이면 수 분. 반드시 `run_in_background: true` 로 실행하고, 끝나면 결과를 읽는다.
- 모델을 처음 쓸 때는 가중치를 내려받느라 더 걸린다.

읽을 때 유의할 점:

- 스피커로 들었다면 내 트랙에 강사 목소리가 새어들 수 있다. 병합 단계가 걸러내지만 완벽하진 않다.
  같은 말이 두 화자로 연달아 나오면 강사 쪽이 원본이다.
- 전사가 잘못 알아들은 대목(고유명사, 겹쳐 말한 구간)은 무리해서 해석하지 않는다.
- `merge_transcript.py` 가 "강사 트랙이 비었다" / "내 트랙이 비었다" 를 경고하면 그대로 사용자에게
  전한다. 녹음 설정 문제이지 수업 내용 문제가 아니다.

전사 원문은 노트에 싣지 않는다. 아래 항목을 뽑는 재료로만 쓴다.
(사용자가 "전사 원문도 넣어줘" 라고 하면 `## 전사` 섹션을 맨 뒤에 추가한다.)

### 3) 노트 작성

경로: `~/mylogs/study/영어수업 YYYY-MM-DD.md` (같은 날 두 번째면 `(2)`).
이미 있으면 덮어쓰지 말고 이어 붙일지 새 파일로 만들지 확인한다.

템플릿은 `references/template.md`. 구성:

1. **수업 요약** — 오늘 다룬 주제·상황 3~5줄.
2. **내 표현 교정** — 내가 말한 어색한 문장을 `내가 한 말 / 자연스러운 표현 / 왜` 표로. 왜는 한 줄.
3. **새 단어·표현** — 처음 나온 어휘·구문을 `표현 / 뜻 / 예문` 표로.
4. **수업 중 질문** — `qa.md` 내용을 정리해 싣는다. 수업 중 답한 것과 전사를 대조해, **실제 수업에서 그 표현을 썼는지 / 튜터가 뭐라 반응했는지** 확인되면 한 줄 덧붙인다.
5. **복습 과제** — 다음 수업 전까지 연습할 것 3~5개, 체크박스. 교정·질문에서 반복된 것을 우선한다.

전사와 질문이 겹치면 합친다. 같은 표현이 교정과 질문 양쪽에 나오면 한쪽에만 쓰고 다른 쪽에서 참조한다.

### 4) 마무리

노트를 저장한 뒤에만 실행한다. 세션 원본(qa.md, 메타)을 보관 폴더로 옮긴다.

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh close
```

저장 경로와 함께 교정 몇 건·새 표현 몇 개·질문 몇 건을 뽑았는지 한 줄로 알린다.
녹화 원본은 `~/Movies/english-class/` 에 그대로 남는다. 지우지 않는다 — 나중에 다시 들어볼 수
있어야 하고, 지울지는 사용자가 정할 일이다. 용량이 쌓이면 정리할 수 있다고만 알려준다.

## 녹음 구조

`audio-recorder`(ScreenCaptureKit 기반 Swift 바이너리, `AudioRecorder.swift` 를 컴파일한 것)가
시스템 오디오와 마이크를 **각각 다른 파일**에 담는다. 오디오 장치 설정을 바꿀 필요가 없고,
헤드셋을 써도 강사 목소리가 시스템 오디오 경로로 잡힌다.

- 바이너리가 없으면 다시 빌드한다:
  `swiftc -O -parse-as-library -o ~/workspace/stueng/skills/english-class/scripts/audio-recorder ~/workspace/stueng/skills/english-class/scripts/AudioRecorder.swift`
- 화면 기록 권한과 마이크 권한이 필요하다. 거부되면 `record.sh start` 가 실패하며 그 사실을 알린다.
- 레벨이 의심스러우면 `audio-recorder <프리픽스> --debug-level` 로 0.5초마다 RMS 값을 찍어 볼 수 있다.
  `--show-popover` 는 팝오버를 자동으로 열어 표시 상태를 확인할 때 쓴다.
- `AudioRecorder.swift` 를 고칠 때 주의: 스트림·라이터 참조를 `Main.retained` 에 담아두지 않으면
  Task 스코프가 끝나면서 캡처가 **조용히** 멈춘다(에러 없이 0.1초짜리 파일이 남는다).
- 중지는 SIGINT 후 최대 30초 대기다. 강제로 죽이면 m4a/mov 가 깨진다.

## 작성 원칙

- 노트 본문은 한국어, 영어 표현·예문은 영어 원문 그대로.
- 교정·어휘는 **실제로 수업이나 질문에 나온 것만** 쓴다. 분량을 채우려고 일반적인 영어 팁을 지어내지 않는다.
- 뽑을 게 없는 섹션은 억지로 채우지 말고 `- 없음`.
- 볼트가 Obsidian이므로 다른 노트 참조는 `[[파일명]]` 위키링크.
