## A. 시작

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh start --tutor "이름" --topic "주제" --no-record
```

**수업은 다른 PC 에서 돌아간다.** 헤드셋을 쓰므로 이 맥의 마이크로도, 시스템 오디오로도
강사 목소리가 잡히지 않는다. 그래서 맥에서는 녹음하지 않고(`--no-record`) 질문 로그만
남긴다. 녹음은 그 PC 가 하고, 수업이 끝나면 파일을 맥으로 넘겨 전사한다(→ C-1).

**수업 시작 전에 그 PC 의 녹음이 돌고 있는지 한 줄 확인시킨다.** 여기서 빠뜨리면 50분
뒤에 전사할 것이 아무것도 없다. 사용자가 녹음을 못 켰다고 하면 그대로 진행하되,
종료 시 전사 없이 질문 로그만으로 노트를 만든다는 것을 알린다.

클릭하면 팝오버가 열려 경과 시간과 **강사 / 나 각각의 음파 파형**을 실시간으로 보여주고,
거기서 바로 "녹음 중지" 를 할 수도 있다.

파형이 말에 맞춰 출렁이면 그 트랙이 살아 있다는 뜻이고, 한쪽이 계속 평평한 기준선이면
그 입력이 안 잡히고 있다는 뜻이다.

- 이미 다른 방법으로 녹화 중이면 `--no-record`, 화면 없이 소리만 남기려면 `--no-video`,
  메뉴 막대가 거슬리면 `--no-menubar`.
- 시작을 알릴 때 **메뉴 막대를 확인하라고 한 줄 덧붙인다.** 수업 초반에 양쪽 막대가
  움직이는지 보면, 50분을 녹음하고 나서야 한쪽이 비었다는 걸 아는 사고를 막을 수 있다.
- 녹화 시작에 실패하면(권한 거부 등) 그 사실을 **반드시 사용자에게 알린다.** 녹화가 없으면
  종료 시 전사할 것도 없다. 조용히 넘어가지 말 것.

- 튜터·주제는 아는 만큼만 넘긴다. 모르면 옵션을 빼고, 굳이 캐묻지 않는다.
- 시작했다고 알리고 — 그 PC 의 녹음 확인 한 줄과 함께 — 수업 중 궁금한 표현을
  물어보라고 안내한 뒤 대기한다. 이후 답변은 짧게 유지한다. 수업 중이라 길게 읽을 시간이 없다.

## B. 수업 중 Q&A

사용자가 표현·문법·단어를 물으면 **간결하게** 답한다.

- 설명 2~3줄 + 예문 2~3개. 예문은 화상 영어 수업/일상 대화 맥락으로.
- 뉘앙스 차이나 더 자연스러운 대안이 있으면 한 줄 덧붙인다.
- 길게 늘어놓지 않는다. 수업 중에 바로 읽고 말해야 한다.

답한 직후 **매번** `~/mylogs/study/.session/qa.md` 에 아래 형식으로 이어 붙인다. 빠뜨리면 종료 시 노트에서 누락된다.

```markdown
## HH:MM Q. (질문)

(설명 한두 줄)

- (예문)
- (예문)
```

## C. 종료

### 1) 재료 모으기 + 녹화 가져오기

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh end
```

세션 메타와 질문 로그(`qa.md`) 경로가 출력된다. `qa.md` 를 읽는다.
(맥에서 녹음했다면 여기서 녹화도 중지된다. 중지는 SIGINT 후 최대 30초 대기라, 그 사이에
강제 종료하면 파일이 깨진다 — `end` 가 끝날 때까지 기다린다.)

**수업 PC 의 녹화를 맥으로 가져온다.** 사용자에게 그 PC 에서 아래를 실행하라고 안내한다
(`scp` 는 윈도우 10 이상·리눅스에 기본으로 있다):

```
scp <녹화파일> <사용자>@<맥의 LAN IP>:~/Movies/english-class/inbox/
```

파일이 들어오면 맥에서:

```bash
~/workspace/stueng/skills/english-class/scripts/import.sh
```

`inbox` 의 가장 최근 파일을 집어 오디오 트랙 두 개를 `<프리픽스>-tutor.m4a` /
`<프리픽스>-me.m4a` 로 쪼갠다. 이 뒤로는 맥에서 녹음한 것과 **완전히 같다.**

- 첫 번째 오디오 트랙을 강사(데스크톱 소리), 두 번째를 나(마이크)로 본다. 전사를 읽어 보고
  뒤바뀌었으면 `--swap` 을 붙여 다시 돌린다.
- "오디오 트랙이 하나뿐" 경고가 나오면 화자 구분을 포기하고 통짜 전사로 간다. 그 경우
  녹음 설정을 고치라고 한 줄 알린다(→ **수업 PC 녹음 설정**).
- 파일이 아직 안 들어왔으면 **멈추고 기다린다.** 다른 파일을 임의로 집지 않는다.
- 녹음을 아예 못 했으면 전사를 건너뛰고 `qa.md` 만으로 노트를 만든다. 그 사실을 노트
  요약에 한 줄 남긴다 — 나중에 이 노트가 왜 얇은지 알 수 있어야 한다.

### 2) 녹화 전사

수업 녹화의 **음성**을 전사한다. 화면 캡처가 아니라 오디오가 원본이다.

`import.sh` 가 출력한 전사 명령을 그대로 실행한다.

```bash
~/workspace/stueng/skills/english-class/scripts/transcribe.sh --prefix "<녹화 프리픽스>"
```

- 두 트랙을 각각 mlx-whisper(large-v3-turbo)로 전사한 뒤 시각 순으로 합쳐
  `~/mylogs/study/.session/transcript.md` 를 만든다. 이걸 읽으면 된다.
- **화자는 추정이 아니라 확정이다.** `Tutor` 는 데스크톱 소리(강사), `Me` 는 마이크에서 왔다.
- 단일 트랙이라 `--file` 형태로 왔으면 화자 구분이 안 된다. 문맥으로 추정하되 애매하면
  `[화자불명]` 으로 둔다. 지어내지 않는다.
- **오래 걸린다.** 50분 수업이면 수 분. 반드시 `run_in_background: true` 로 실행하고, 끝나면 결과를 읽는다.
- 모델을 처음 쓸 때는 가중치를 내려받느라 더 걸린다.

읽을 때 유의할 점:

- 스피커로 들었거나 마이크가 데스크톱 소리를 되받으면 내 트랙에 강사 목소리가 새어들 수 있다.
  병합 단계가 걸러내지만 완벽하진 않다. 같은 말이 두 화자로 연달아 나오면 강사 쪽이 원본이다.
- 전사가 잘못 알아들은 대목(고유명사, 겹쳐 말한 구간)은 무리해서 해석하지 않는다.
- `merge_transcript.py` 가 "강사 트랙이 비었다" / "내 트랙이 비었다" 를 경고하면 그대로 사용자에게
  전한다. 녹음 설정 문제이지 수업 내용 문제가 아니다.

전사 원문은 노트에 싣지 않는다. 아래 항목을 뽑는 재료로만 쓴다.
(사용자가 "전사 원문도 넣어줘" 라고 하면 `## 전사` 섹션을 맨 뒤에 추가한다.)

### 3) 노트 작성

경로: `~/mylogs/study/영어수업 YYYY-MM-DD.md` (같은 날 두 번째면 `(2)`).
이미 있으면 덮어쓰지 말고 이어 붙일지 새 파일로 만들지 확인한다.

템플릿은 `references/template.md`. 구성:

1. **수업 요약** — 오늘 다룬 주제·상황 3~5줄.
2. **내 표현 교정** — 내가 말한 어색한 문장을 `내가 한 말 / 자연스러운 표현 / 왜` 표로. 왜는 한 줄.
3. **새 단어·표현** — 처음 나온 어휘·구문을 `표현 / 뜻 / 예문` 표로.
4. **수업 중 질문** — `qa.md` 내용을 정리해 싣는다. 수업 중 답한 것과 전사를 대조해, **실제 수업에서 그 표현을 썼는지 / 튜터가 뭐라 반응했는지** 확인되면 한 줄 덧붙인다.
5. **복습 과제** — 다음 수업 전까지 연습할 것 3~5개, 체크박스. 교정·질문에서 반복된 것을 우선한다.

전사와 질문이 겹치면 합친다. 같은 표현이 교정과 질문 양쪽에 나오면 한쪽에만 쓰고 다른 쪽에서 참조한다.

### 4) 마무리

노트를 저장한 뒤에만 실행한다. 세션 원본(qa.md, 메타)을 보관 폴더로 옮긴다.

```bash
~/workspace/stueng/skills/english-class/scripts/session.sh close
```

**노트를 서버로 보낸 뒤에 `close` 한다** (→ "수업 PC 에서 바로 보내기"). 이 PC 에서
돌고 있다면 노트가 여기 남을 뿐 복습 앱으로 가지 않는다.

저장 경로와 함께 교정 몇 건·새 표현 몇 개·질문 몇 건을 뽑았는지 한 줄로 알린다.
가져온 녹화(`inbox/` 원본과 쪼갠 m4a)는 `~/Movies/english-class/` 에 그대로 남는다. 지우지 않는다 — 나중에 다시 들어볼 수
있어야 하고, 지울지는 사용자가 정할 일이다. 용량이 쌓이면 정리할 수 있다고만 알려준다.

## 수업 PC 녹음 설정

수업이 도는 PC 가 **오디오 트랙 두 개**(데스크톱 소리 = 강사, 마이크 = 나)를 한 파일에
담아야 한다. 그래야 맥에서 화자가 확정된다. 한 트랙으로 뭉뚱그리면 전사는 되지만 누가
한 말인지 모르게 되고, 교정 표를 뽑는 근거가 사라진다.

OBS Studio (윈도우·리눅스 공통) 기준:

1. 설정 → 출력 → **출력 모드: 고급** (단순 모드는 다중 트랙을 지원하지 않는다)
2. 녹화 탭 → 녹화 형식 **mkv**, 오디오 트랙 **1 과 2 를 체크**
3. 오디오 믹서에서 톱니 → 오디오 고급 속성
   - 데스크톱 오디오 → 트랙 **1** 만
   - 마이크 → 트랙 **2** 만
4. 수업 시작 전에 두 미터가 다 움직이는지 확인한다.

한 컨테이너 안의 두 트랙은 같은 클럭에서 나오므로 어긋남이 없다. `import.sh` 가
`sync.json` 을 offset 0 으로 써 둔다 — 맥 녹음과 달리 트랙 싱크를 걱정할 필요가 없다.

전송은 그 PC 에서 맥으로 `scp` 다. 맥은 원격 로그인이 켜져 있고 받는 곳은
`~/Movies/english-class/inbox/` 다. 주소와 사용자명은 이 저장소가 공개라 적지 않는다 —
맥의 LAN 주소는 그 맥에서 `ipconfig getifaddr en0`, 사용자명은 `whoami` 로 확인한다.

**이 경로는 같은 와이파이일 때만 된다.** 사설 IP 라 밖에서는 닿지 않는다. 밖에서
작업한다면 아래 "수업 PC 에서 바로 보내기" 를 쓴다 — 그쪽은 공인 주소라 어디서든 된다.

## 수업 PC 에서 바로 보내기

**이 스킬이 그 PC 에서 돌고 있다면 C-3 에서 쓴 노트가 거기 쌓인다.** 맥의
`vocab.collect` 는 맥의 폴더만 훑으므로, 그 노트는 그냥 두면 아무 데도 가지 않는다.
`close` 직전에 한 줄 보내면 된다.

```bash
python -m vocab.remote --note "~/mylogs/study/영어수업 2026-08-28.md"
python -m vocab.remote --note "..." --dry-run      # 무엇이 갈지만 본다
```

**뜻·예문·교정이 이미 다 들어 있다.** 그 노트를 쓴 것이 이 PC 의 Claude 이기 때문이다.
표를 읽는 규칙은 `vocab.notes` 에 있고 맥의 `collect` 와 **같은 코드**라, 두 경로로
들어와도 결과가 어긋나지 않는다. 교정 표는 `correction` 출처로 따로 들어가는데,
출제 순서에서 가장 먼저 오는 재료다.

### 노트에 안 담긴 것까지 줍고 싶으면

전사문에서 반복된 낱말을 빈도 기준으로 뽑는 보조 경로가 있다.

```bash
python -m vocab.remote --transcript "~/mylogs/study/.session/transcript.md"
python -m vocab.remote --audio class.mkv --model small   # 전사부터 여기서
```

이쪽은 **뜻을 비운 채** 간다. 후보 선정은 규칙(빈도 밴드 + 반복 횟수)이라 옮겨지지만,
뜻은 LLM 이 필요하고 이건 사람이 부르는 자리가 아니다. 서버는 그 어휘를 카드로 만들지
않은 채 쌓아 두고, 맥에서 `python -m vocab.tutor` 가 돌 때 채워져 출제된다. 밀려도 빈
문제가 나가지는 않는다 — 새 카드가 늦어질 뿐이다.

로그에 "학습 상태를 못 받았습니다" 또는 "거부당했습니다" 가 뜨면 **멈추고 토큰을
확인한다.** 그게 뜬 채로 돌면 이미 외우는 중인 단어가 후보 자리를 차지한다.

그 PC 준비:

```bash
git clone <이 저장소> stueng && cd stueng
pip install wordfreq simplemma requests
pip install faster-whisper            # --audio 를 쓸 때만

export VOCAB_SERVER_URL=https://stueng.deepheart.duckdns.org
export VOCAB_REMOTE_TOKEN=<게이트웨이 .env 의 VOCAB_REMOTE_TOKEN>
```

이게 전부다. 게이트웨이(Traefik)가 이미 이 이름을 Let's Encrypt 인증서로 서비스하고
있고, DuckDNS 가 공인 IP 를 따라가며 갱신한다. **집 밖에서는 그냥 닿는다** — 열 포트도,
터널도, hosts 손질도 없다. 보안 헤더와 rate limit(분당 100)도 그대로 걸린다.

주소는 반드시 **이름**으로 쓴다. 공인 IP 는 바뀌고, 그걸 따라가라고 DuckDNS 가 있다.

<details>
<summary>집 안(같은 와이파이)에서 보낼 때만 — hosts 한 줄</summary>

공유기가 헤어핀 NAT 을 지원하지 않아, 집 안에서는 공인 주소로 되돌아오지 못한다.
그때만 이름을 LAN IP 로 풀어 준다. (리눅스 `/etc/hosts`, 윈도우
`C:\Windows\System32\drivers\etc\hosts` — 관리자 권한)

```
<맥의 LAN IP>  stueng.deepheart.duckdns.org
```

(맥의 LAN 주소는 그 맥에서 `ipconfig getifaddr en0`, 사용자명은 `whoami` 로 확인한다. 이 저장소는 공개라 실제 값을 적지 않는다.)

Traefik 의 443 은 LAN 에도 열려 있고 인증서는 이름에 대해 발급된 것이라, 이렇게 해도
검증이 정상으로 통과한다. TLS 검증을 끄거나 http 로 우회할 이유는 없다.

**집 밖으로 나가면 이 줄을 지운다.** 남겨 두면 닿지 않는 사설 IP 를 계속 찾는다.
그래서 밖에서 올리는 게 기본이라면 아예 넣지 않는 편이 낫다.

### 토큰은 좁은 것을 쓴다

`VOCAB_INGEST_TOKEN` 은 기계용 엔드포인트 여섯 개를 전부 여는 열쇠다. 거기에
`/api/export` 가 있는데, 이건 어휘뿐 아니라 **복습 기록까지 담긴 DB 전체 덤프**다.
그 기록은 서버에만 있는 유일한 데이터라 어휘와 달리 다시 만들 수 없다.

수업 PC 는 어휘를 넣기만 하면 된다. 그래서 `/ingest` 에서만 통하는
`VOCAB_REMOTE_TOKEN` 을 따로 둔다. 그 PC 에서 새더라도 잃는 것은 쓰기 권한 하나이고,
어휘는 로컬에서 다시 만들 수 있다. 읽기는 넘어가지 않는다.

값은 게이트웨이 `.env` 에 있다. 맥에서:

```bash
grep VOCAB_REMOTE_TOKEN ~/workspace/deepheart-gw/.env
```

좁은 토큰이 여는 것은 `/ingest`(어휘 넣기)와 `/api/handled`(이미 다루는 표제어 목록,
후보에서 뺄 것) 둘뿐이다. `/api/export`·`/api/tasks`·`/api/progress` 는 401 이다.

`vocab.remote` 는 좁은 토큰을 먼저 찾고, 없으면 넓은 것으로 돌아가되 경고를 남긴다.
평문 HTTP 주소로는 아예 보내지 않는다 — 토큰이 그대로 나가기 때문이다.

**어느 길을 쓸지.** 둘은 배타적이지 않다. 표제어가 겹치면 서버가 합치고, 원격이 비워 둔
뜻은 나중에 들어온 수업 노트가 채운다. 교정 표가 나올 만한 수업이면 노트를 쓰고,
그냥 흘려보내기 아까운 정도면 원격으로 밀어만 둔다.

## 맥에서 녹음할 때의 구조

수업을 이 맥에서 들을 때만 해당한다. 다른 PC 수업이면 이 절 전체를 건너뛴다.

`audio-recorder`(ScreenCaptureKit 기반 Swift 바이너리, `AudioRecorder.swift` 를 컴파일한 것)가
시스템 오디오와 마이크를 **각각 다른 파일**에 담는다. 오디오 장치 설정을 바꿀 필요가 없고,
헤드셋을 써도 강사 목소리가 시스템 오디오 경로로 잡힌다.

- 바이너리가 없으면 다시 빌드한다:
  `swiftc -O -parse-as-library -o ~/workspace/stueng/skills/english-class/scripts/audio-recorder ~/workspace/stueng/skills/english-class/scripts/AudioRecorder.swift`
- 화면 기록 권한과 마이크 권한이 필요하다. 거부되면 `record.sh start` 가 실패하며 그 사실을 알린다.
- 레벨이 의심스러우면 `audio-recorder <프리픽스> --debug-level` 로 0.5초마다 RMS 값을 찍어 볼 수 있다.
  `--show-popover` 는 팝오버를 자동으로 열어 표시 상태를 확인할 때 쓴다.
- `AudioRecorder.swift` 를 고칠 때 주의: 스트림·라이터 참조를 `Main.retained` 에 담아두지 않으면
  Task 스코프가 끝나면서 캡처가 **조용히** 멈춘다(에러 없이 0.1초짜리 파일이 남는다).
- 중지는 SIGINT 후 최대 30초 대기다. 강제로 죽이면 m4a/mov 가 깨진다.

### 트랙 싱크

두 스트림의 첫 버퍼가 도착하는 시각은 다르다(마이크 워밍업 등). 각 m4a 의 `t=0` 은
**그 트랙의 첫 샘플**이므로, 보정하지 않으면 늦게 시작한 트랙의 발화가 실제보다
이른 시각에 찍힌다. 소리만 들어서는 절대 드러나지 않는 종류의 어긋남이다.

- 녹음기가 `<프리픽스>-sync.json` 에 트랙별 `offset`(세션 원점 대비 시작 지연)과
  `dropped`(인코더가 밀려 놓친 샘플 수)를 남긴다.
- `record.sh stop` 이 그 값을 읽어 "트랙 싱크 정상 (어긋남 0.10초)" 처럼 한 줄 알린다.
  0.5초 이상 어긋났거나 유실이 있으면 경고로 바꿔 띄운다.
- `merge_transcript.py` 가 `offset` 을 각 트랙 시각에 더해 병합한다. `sync.json` 이 없는
  구버전 녹음은 보정 없이 진행하되 그 사실을 알린다.
- **두 파일의 길이가 다른 것 자체는 이상이 아니다.** 수업이 끝나 Zoom 이 마이크를 놓으면
  마이크 스트림이 먼저 끝나고, 시스템 오디오는 중지할 때까지 무음을 계속 기록한다.
  실제 어긋남인지는 길이가 아니라 `sync.json` 의 `offset` 으로 판단한다.

### 전사가 같은 말을 반복하면

whisper 가 이전 문맥을 계속 참조하다 `Yeah.` / `Hmm.` 같은 짧은 말에 갇히는 일이 있다.
수십 분 분량이 통째로 같은 문장으로 채워지므로 바로 알아볼 수 있다. `transcribe.sh` 는
`--condition-on-previous-text False` 로 이를 막는다 — 이 옵션을 지우지 말 것.

## 작성 원칙

- 노트 본문은 한국어, 영어 표현·예문은 영어 원문 그대로.
- 교정·어휘는 **실제로 수업이나 질문에 나온 것만** 쓴다. 분량을 채우려고 일반적인 영어 팁을 지어내지 않는다.
- 뽑을 게 없는 섹션은 억지로 채우지 말고 `- 없음`.
- 볼트가 Obsidian이므로 다른 노트 참조는 `[[파일명]]` 위키링크.
